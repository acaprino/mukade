# Linux verification — 2026-11-11

**Where:** a Linux container (kernel 6.18, x86_64), Rust 1.97, Claude Code 2.1.322 installed and
running. No Codex, OpenCode or Pi binary on this machine.

**Result in one line:** two bugs found and fixed, the whole test suite green on Linux for the first
time (519 tests, `cargo test --workspace --no-fail-fast`).

## 1. `live` for Claude Code on Linux

| | |
|---|---|
| **Was** | `[U]` — never run off Windows |
| **Found** | **bug**: every running session read `live: null` |
| **Why** | Claude Code on Linux writes `pidDomain` as `linux:<machine id>:pid:[<pid namespace>]`. mukade compared the machine part with the host name (`vm`), not the machine id (`/etc/machine-id`), so it judged every registration "another machine" |
| **Also found** | `procStart` on Linux is field 22 of `/proc/<pid>/stat` (clock ticks since boot): `"153"` for pid 94, equal to `/proc/94/stat` |
| **Fix** | match the machine id (or host name), compare the pid namespace with `/proc/self/ns/pid`, compare `procStart` exactly with `/proc/<pid>/stat`; a zombie process is gone (`src/reader/claude_live.rs`, `src/process.rs`) |

The registration that was read (`~/.claude/sessions/94.json`, trimmed):

```json
{"pid":94,"sessionId":"10ec6498-…","procStart":"153","version":"2.1.322",
 "pidDomain":"linux:d165c2d88d894a4787be219662b439ad:pid:[4026531836]","status":"busy"}
```

What `mukade list claude_code` says, after the fix:

| case | `live` |
|---|---|
| the real running session | `true` ✅ |
| same file, `procStart` changed to `154` (a reused pid) | `false` ✅ |
| same file, another pid namespace `pid:[1]` | `null` ✅ (cannot be judged from here) |

## 2. A timeout stops the whole process tree

| | |
|---|---|
| **Was** | `[U]` — "only the process itself is stopped outside Windows" |
| **Reproduced** | a test runs `sh -c '<grandchild> & sleep 60'` with a 0.5 s deadline: the grandchild was **still running** after the timeout |
| **Fix** | `kill_tree` reads the tree from parent ids (`/proc`, or `ps -A` without it), sends `SIGSTOP` (so it cannot grow), reads it again, then `SIGKILL` — through the system `kill`, no new dependency, no FFI |
| **Kept** | the child stays in mukade's process group, so **Ctrl-C still reaches the harness** |
| **After** | the same test passes: the grandchild is gone (`src/exe.rs`, test `a_timeout_stops_what_the_command_started`) |
| **Limit** | a process that detached itself (a daemon that re-parented to init) is not found |

## 3. The test suite on Linux

Three tests had only ever passed on Windows. None was a product bug:

| test | why it failed on Linux | fix |
|---|---|---|
| 4 × `opencode_import` | fake `opencode` scripts call `cp`, but the tests run mukade with an empty `PATH` (on Windows `copy` is built into `cmd`) | the fake launcher adds `/usr/bin:/bin` to its own `PATH` only |
| `portable::mukade_keeps_every_file…` | expected order `mukade-data` < `mukade.exe`; a bare `mukade` sorts first | compare both sides sorted |
| `listing_coverage::a_process_id_taken…` | written for FILETIME units only | per-platform expectations |

Final run: **26 test binaries, 519 tests, 0 failures**.
