# Live check: the local chat service and a real MCP client

| | |
|---|---|
| **Date** | 2026-11-12 |
| **Machine** | Windows 11, debug build of branch `wip/mcp-chat` after merging `origin/master` `883b8d7` |
| **Client** | Claude Code (installed version), model `haiku`, one turn |
| **Result** | lifecycle works; a real harness lists rooms through the MCP endpoint |

## What was run

1. `mukade chat status` on an empty scratch `MUKADE_DATA_DIR`: `stopped`, no file created.
2. `mukade chat start`: `running`, endpoint `http://127.0.0.1:<port>/mcp`.
3. `mukade chat open --name prova`, `mukade chat rooms`: the room is listed.
4. `claude -p --model haiku --mcp-config <temporary file> --strict-mcp-config --allowedTools mcp__mukade__chat_rooms --no-session-persistence "Call the mukade chat_rooms tool and reply with only the room names you get."` answered `prova`. The temporary file named the endpoint and the two headers; no user configuration was changed.
5. `mukade chat stop`: `stopped`; `status` after it: `stopped`.

## Tests at this state

`cargo test -j 4 --workspace`: 796 passed, 3 failed. The 3 (`harness_inventory_*` in `tests/cli.rs`) failed only because the scratch root was given with forward slashes; with a native path they pass (9 of 9), and `tests/architecture.rs` passes.
