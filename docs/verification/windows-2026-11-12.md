## Findings (fixed the same day, after the author's go)

Each is fixed and checked live with the debug build; the details below are what was seen before.

| finding | fix | live |
|---|---|---|
| 1 provider | `model_provider` is Codex's default `openai` when nothing names one | a Claude Code and a Codex Desktop source hopped into Codex with no flag: both resume |
| 2 screen | `history_mode: "paginated"` and `item_completed` events (`UserMessage`, `AgentMessage`, `CommandExecution`); every turn another prompt follows ends with `task_complete` | prompts and answers drawn, no `Conversation interrupted`; a Codex CLI thread's last turn draws `• Ran rg -n …` with its output, as the native thread does |
| 3 dangling parent | the row is read after the row before it, `Meta(Relinked)`, counted as `relinked_parents` | the 98 MB transcript hops into Pi in 10.6 s (debug build), `rows whose parent the source file does not hold, read after the row before them (1)` |
| 4 Pi provider | a Claude Code model is written with `provider: "anthropic"` | 6 assistant messages `anthropic`/`claude-sonnet-5-5` |

Found on the way: a mukade-written thread without `history_mode` is never projected into
`thread_history_1.sqlite`; a clone of a native thread without its `item_completed` events draws
nothing either. The older `user_message`/`agent_message` events draw prompts and answers but no
commands, so the native shape was chosen. Throwaway copies were removed with `codex delete --force`.


1. **Codex refuses to resume a written thread when the destination names no provider.** The
   writer writes `session_meta.model_provider` only from `--model-provider` or a top-level
   `model_provider` in `config.toml`; this one names only `model`. Codex indexes the thread with
   `model_provider = ''` and `codex resume` ends ``thread/resume failed: failed to load
   configuration: Model provider `` not found (code -32600)``. With `--model-provider openai` it
   resumes. Codex's own default, when its config names none, is `openai`.
2. **Codex's interface shows none of a written thread's history.** Codex 0.167 rebuilds the
   screen from `event_msg item_completed` records (`UserMessage`, …; 98 in one native CLI thread);
   the writer writes `response_item`s only, which the model reads but the screen does not. The
   written thread also has 5 `task_started` and 2 `task_complete`: the screen prints
   `■ Conversation interrupted` three times.
3. **One dangling parent refuses a whole Claude Code session.** In a real 98 MB transcript one
   assistant row's `parentUuid` names a row that exists nowhere (`could not read the source:
   missing Claude Code parent 0f8f5b9e-…`). The docs name the case for children only.
4. **Pi gets a model without a provider from Claude Code.** The written assistant message has
   `model` and no `provider`; Pi warns `Could not restore model undefined/claude-haiku-5-5` and
   takes its default. The TUI's import offers no `--model-provider`.

## On the way

  choices write the config), then "Hooks need review" (`esc` skips; nothing trusted, no hook runs).
  Started from a trusted project (here `D:\Projects\mukade`) there is no trust question.

  discovery failed`. The daemons these runs started were stopped afterwards.

  escape sequence whole, and the runs after it quit with Ctrl+C and press no Enter.
